Something I've been chewing on. Reviewing sixty diffs doesn't scale and I don't think the answer is reviewing them faster. What actually goes wrong in a long autonomous run isn't bad lines, it's decisions — by the time there's a PR in front of me, three choices have been made that everything else now rests on, and arguing with one of them means unwinding the other two. Finding out in a nine hundred line diff that the wrong idempotency key got picked is the most expensive possible moment to find out. So the leverage is reviewing the decision before the code exists, and the code review after that is nearly mechanical. I'm not sure where the line is between what needs that and what doesn't, honestly.
