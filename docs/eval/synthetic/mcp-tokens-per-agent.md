Question I want to think about out loud. When an agent hits one of my MCP servers, should the token identify the agent or the service it's calling on behalf of? Per-agent means I can revoke one agent without touching anything else and the audit log actually tells me who did what, which is obviously nicer. But it also means minting a token every time I spin up a new agent, and I know from experience that whatever is annoying to do gets done once badly and then copy-pasted. Per-service is easier to live with and much worse to investigate afterwards. There's probably a middle where the token is per-service but carries the agent identity as a claim, I don't know if that's over-thinking it.
