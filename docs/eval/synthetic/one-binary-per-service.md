I've noticed the services I actually enjoy operating are the ones that are a single static binary with the migrations embedded in them. There's no step where the schema and the code can disagree, because they ship together. No migration tool to install, no ordering problem on deploy, no separate container that has to run first. The ones that annoy me are the ones with three moving parts that all have to be the right version at the same time. So that's the house style now and it's not really up for discussion — new Go service, one binary, embedded migrations, applied on boot.
