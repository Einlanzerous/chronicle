I keep going back and forth on how Purser should handle deprovision when someone's in more than one service. Like if I pull somebody out, do I revoke the Cloudflare Access grant first and then clean up the per-service accounts, or the other way round? Revoking Access first means they're locked out immediately, which is what you want if the reason you're deprovisioning is bad. But it also means the connectors then have to clean up accounts for a person who can't be reached, and if one of them fails halfway you've got a half-removed person and no way to log back in and check. The other order is tidier but leaves a window. I don't think there's an obvious answer and I'd want to actually look at what each connector does on failure before committing to one.
